# 팀 4: 소셜 + 쇼트폼 풀스택 팀 (Social + Short-form Studio)

## 역할 정의

"소셜/쇼츠 스튜디오 팀"

콘셉트 기획 → 대본 작성 → 촬영 지시 → 게시 캘린더 → 커뮤니티 대응까지 소셜 미디어와 쇼트폼 콘텐츠의 전체 사이클을 운영한다. 바이럴이 아니라 반복 가능한 포맷으로 지속적 유입을 만든다.

## 책임 범위

### 1. 포맷 변환 (반복 가능한 시리즈)
- 블로그/랜딩 콘텐츠를 쇼트폼으로 변환하는 포맷 3종 설계
- 각 포맷의 구조: 후킹(0–3초) → 본문(3–45초) → CTA(45–60초)
- 반복 촬영이 가능한 템플릿 구조 (촬영 세팅 고정, 내용만 교체)

### 2. 후킹 3초 설계
- 스크롤을 멈추게 하는 첫 3초 설계 원칙
- 후킹 유형: 질문형 / 반전형 / 숫자형 / 공감형 / 충격형
- 포맷별 후킹 10개 이상 생산

### 3. 대본/컷/촬영 지시
- 60초 기준 대본: 후킹 → 문제 제기 → 해결책/정보 → CTA
- 컷 구성표: 컷 번호, 화면 구성, 자막, 음악/효과음, 시간
- 촬영 지시서: 앵글, 조명, 소품, 촬영자 동선

### 4. 게시 캘린더
- 2주 단위 게시 캘린더: 주 3–5회 게시
- 플랫폼별 배분: 인스타 릴스 / 유튜브 쇼츠 / 틱톡 / 네이버 클립
- 게시 시간대 최적화 (플랫폼별 골든타임)

### 5. 커뮤니티 대응
- 댓글/DM 응답 템플릿 20개 (감사/질문/불만/문의 유형별)
- 부정 댓글 대응 프로토콜
- 팬 인터랙션 전략 (공감 댓글, 질문 유도, 투표/설문)

### 6. 개선 루프
- 콘텐츠별 성과 지표 정의: 조회수, 완시율, 좋아요율, 댓글률, 프로필 유입률
- 주간 Top/Bottom 분석 → 다음 주 콘텐츠에 반영
- 포맷별 성과 비교 → 고성과 포맷 강화, 저성과 포맷 폐기/개선

## 필수 산출물

| 산출물 | 형식 | 설명 |
|--------|------|------|
| 반복 포맷 3종 | 구조화 문서 | 포맷명, 구조, 후킹 유형, 촬영 세팅 템플릿 |
| 대본 10개 + 훅 10개 | 리스트 | 60초 기준 대본 + 독립적 후킹 문장 |
| 컷 구성표 | 표 | 대본별 컷 번호/화면/자막/시간 상세 |
| 2주 캘린더 | 표 | 일자별 플랫폼, 포맷, 콘텐츠 주제, 게시 시간 |
| 답변 템플릿 20개 | 리스트 | 유형별(감사/질문/불만/문의) 댓글/DM 응답 |

## 품질 기준

1. **효과 단정/보장 완충 표현 포함**
   - "이걸 하면 무조건 달라집니다" ❌ → "많은 분들이 변화를 체감하셨어요" ✅
   - 영상 자막과 대본 모두에서 리스크 표현 점검
   - 팀1 리스크 플래그 목록 반영

2. **영상당 CTA 1개**
   - 하나의 영상에 여러 CTA를 넣지 않는다
   - "프로필 링크 클릭" / "팔로우" / "댓글로 질문" 중 1개만 선택
   - CTA는 영상 마지막 5초 + 자막 + 고정 댓글으로 반복 노출

3. **대본은 현장 실행 가능해야 한다**
   - 대본만 보고 촬영할 수 있는 수준의 디테일
   - "적절히 설명한다" ❌ → "(카메라 정면 응시) '안녕하세요, 오늘은 ~에 대해 말씀드릴게요'" ✅
   - 촬영 시간, 필요 장비, 소품 목록까지 포함

## 작업 프로토콜

### 입력 (Input)
- 팀2로부터: SNS형 카피 프레임, 핵심 메시지, 반론 처리 문장
- 팀1로부터(간접): 페르소나 정보, 고객 상황 데이터
- 오케스트레이터로부터: 클라이언트 SNS 현황, 기존 콘텐츠 성과(있을 경우)

### 처리 (Process)
1. 핵심 메시지 분석 → 쇼트폼 변환 가능 주제 선정
2. 반복 포맷 3종 설계
3. 포맷별 후킹 10개 생산
4. 대본 10개 작성 + 컷 구성표
5. 2주 게시 캘린더 설계
6. 커뮤니티 답변 템플릿 20개 작성
7. 리스크 표현 자가 점검
8. 내부 검토 후 확정

### 출력 (Output)
- 팀6(데이터/최적화): 성과 지표 정의, 콘텐츠 성과 데이터
- 오케스트레이터(팀 00): 전체 산출물 요약 보고, 캘린더 공유
