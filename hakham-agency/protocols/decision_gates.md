# 품질 게이트 판정 기준

> 하캄 에이전시 산출물 품질 관리를 위한 3단계 판정 체계

---

## 1. 판정 등급 정의

### 통과 (Pass)
- 산출물이 **즉시 실행 가능한 상태**
- 컴플라이언스 이슈 없음
- 모든 필수 항목 충족
- 후속 팀이 추가 질의 없이 작업 착수 가능
- **결과**: 다음 팀으로 핸드오버 진행

### 수정 (Revise)
- 산출물의 **기본 방향은 적합**하나 부분 수정 필요
- 수정 사항이 구체적으로 명시됨
- **24시간 이내 재제출** 의무
- 2회 연속 수정 판정 시 PM 개입
- **결과**: 원 팀으로 반환, 수정 포인트 리스트 첨부

### 반려 (Reject)
- **근본적 재작업** 필요
- 방향성 자체가 잘못되었거나 핵심 요구사항 미충족
- 반려 사유를 상세히 기술 (최소 3줄)
- **결과**: 요청 티켓 단계부터 재검토, PM 에스컬레이션 자동 발동

---

## 2. 공통 판정 기준 체크리스트

모든 산출물에 공통 적용되는 체크리스트. 하나라도 미충족 시 통과 불가.

| # | 항목 | 판정 |
|---|------|------|
| 1 | 핸드오버 포맷이 빠짐없이 작성되었는가 | Pass / Fail |
| 2 | 네이밍 컨벤션을 준수했는가 (파일명, 버전) | Pass / Fail |
| 3 | 타깃 페르소나가 명시되어 있는가 | Pass / Fail |
| 4 | 적용 채널이 명확히 지정되어 있는가 | Pass / Fail |
| 5 | 기한 내 제출되었는가 | Pass / Fail |
| 6 | 이전 팀의 산출물을 정확히 반영했는가 | Pass / Fail |
| 7 | 사실 관계가 검증 가능한 근거에 기반하는가 | Pass / Fail |
| 8 | 맞춤법/표기법 오류가 없는가 | Pass / Fail |
| 9 | 내부 용어와 외부 공개 표현이 구분되어 있는가 | Pass / Fail |
| 10 | 다음 팀의 작업에 필요한 정보가 충분히 포함되었는가 | Pass / Fail |
| 11 | CTA(Call to Action)가 명확하게 포함되었는가 | Pass / Fail |
| 12 | KPI 또는 성과 지표와의 연결이 명시되었는가 | Pass / Fail |

## 3. 컴플라이언스 게이트 (별도 체크)

컴플라이언스 게이트는 공통 체크리스트와 별개로 **독립 심사**한다.
컴플라이언스 1건이라도 위반 시 **즉시 반려**, 예외 없음.

| # | 항목 | 상세 |
|---|------|------|
| C1 | **최상급 표현 금지** | "최고", "1위", "가장", "업계 최초" 등 — 입증 불가 시 사용 금지 |
| C2 | **의료/건강 표현 제한** | 질병 치료/예방 암시 금지 (식약처/건강기능식품법) |
| C3 | **비교광고 기준** | 경쟁사 직접 비교 시 객관적 데이터 필수, 비하 표현 금지 |
| C4 | **개인정보 보호** | 고객 데이터 노출 금지, 익명화 확인, 동의 범위 준수 |
| C5 | **저작권 확인** | 이미지/음원/폰트 라이선스 확인, 출처 명시 |
| C6 | **광고 표시 의무** | 유료 광고/협찬 콘텐츠 명확히 표기 ("광고", "유료광고포함" 등) |
| C7 | **타깃 연령 제한** | 미성년자 대상 부적절 표현 여부 확인 |
| C8 | **할인/가격 표시** | 할인율 산정 근거, 정상가 표기 정확성, 기간 한정 명시 |
| C9 | **후기/리뷰 사용** | 실제 후기 여부 확인, 과장/조작 금지, "개인 의견" 명시 |
| C10 | **플랫폼 정책 준수** | 각 채널(메타, 구글, 틱톡 등)의 광고 정책 위반 여부 |

## 4. 팀별 산출물 품질 기준

### 팀1: 리서치/오퍼 (T01)

**산출물: 페르소나 정의서**
| # | 기준 | 통과 조건 |
|---|------|-----------|
| 1 | 세그먼트 수 | 최소 3개 세그먼트 도출 |
| 2 | 데이터 기반 | 정량 데이터(설문/구매 이력) + 정성 데이터(인터뷰/관찰) 모두 포함 |
| 3 | 페르소나 구성 요소 | 인구통계, 심리, 행동, 미디어 습관, 구매 동기 전부 포함 |
| 4 | 구매 여정 맵 | 인지-탐색-비교-구매-재구매 단계별 터치포인트 매핑 |
| 5 | 경쟁사 분석 | 최소 3개 경쟁사 포지셔닝 비교 |

**산출물: 오퍼 구조**
| # | 기준 | 통과 조건 |
|---|------|-----------|
| 1 | 가치 제안 | 각 페르소나별 핵심 가치 제안 1개 이상 |
| 2 | 가격 전략 | 가격대, 할인 구조, 번들링 옵션 포함 |
| 3 | 차별화 포인트 | 경쟁사 대비 차별화 요소 3개 이상 |
| 4 | 증거 자료 | 효능/효과 뒷받침 데이터, 인증, 수상 내역 정리 |
| 5 | 시즌/시의성 | 출시 시점과의 시의성 검토 완료 |

### 팀2: 전략/크리에이티브 (T02)

| # | 기준 | 통과 조건 |
|---|------|-----------|
| 1 | 메시지 프레임워크 | 페르소나별 핵심 메시지, 보조 메시지, 톤앤매너 정의 |
| 2 | 헤드라인 다양성 | 페르소나당 최소 5개 헤드라인 후보 (감성/이성/긴급성/호기심 등 혼합) |
| 3 | 채널별 톤 가이드 | 채널 특성에 맞는 톤앤매너 차이 명시 |
| 4 | 메시지 일관성 | 전 채널에서 브랜드 핵심 메시지가 일관되게 유지되는지 확인 |
| 5 | 랜딩페이지 IA | 히어로-문제제기-솔루션-증거-CTA 구조 완성 |
| 6 | 비주얼 디렉션 | 무드보드, 컬러 팔레트, 레이아웃 방향 포함 |
| 7 | A/B 테스트 요소 | 테스트할 변수 최소 2개 제안 |

### 팀3: 콘텐츠/SEO (T03)

| # | 기준 | 통과 조건 |
|---|------|-----------|
| 1 | 키워드 클러스터 | 메인 키워드 + 롱테일 키워드 그룹 최소 5개 클러스터 |
| 2 | 검색 의도 분류 | 각 키워드의 검색 의도(정보/상업/거래/탐색) 분류 완료 |
| 3 | 콘텐츠 캘린더 | 최소 4주 분량, 게시 채널/형식/키워드/CTA 명시 |
| 4 | 콘텐츠 구조 | H1-H2-H3 계층 구조, 메타 디스크립션 포함 |
| 5 | 내부 링크 전략 | 기존 콘텐츠와의 연결 구조 설계 |
| 6 | 콘텐츠 길이 | 채널별 권장 길이 준수 (블로그 2000자+, SNS 150자 이내 등) |
| 7 | 원본성 확인 | 표절 검사 결과 유사도 10% 이하 |

### 팀4: 소셜/쇼트폼 (T04)

| # | 기준 | 통과 조건 |
|---|------|-----------|
| 1 | 대본 완성도 | 나레이션, 자막, 화면 지시가 모두 포함된 완성 대본 |
| 2 | 훅 효과 | 3초 이내 시선 고정 장치 (질문/충격/공감/대비 등) |
| 3 | 촬영 지시 구체성 | 앵글, 조명, 소품, 모델 동선, 컷 전환 타이밍 명시 |
| 4 | 분량 적합성 | 릴스 30초/60초, 틱톡 15초/30초/60초 규격 준수 |
| 5 | CTA 삽입 | 영상 끝 5초 이내 CTA (댓글/저장/링크인바이오/팔로우) |
| 6 | 트렌드 반영 | 현재 플랫폼 트렌드(음원/챌린지/포맷) 활용 여부 |
| 7 | 자막 가독성 | 자막 크기, 위치, 배경 처리 기준 명시 |

### 팀5: 퍼포먼스 (T05)

| # | 기준 | 통과 조건 |
|---|------|-----------|
| 1 | 캠페인 구조 | 캠페인-광고세트-소재 3계층 구조 설계 완료 |
| 2 | 타깃팅 매트릭스 | 페르소나별 타깃팅 조건 (관심사/행동/인구통계/리타깃팅) |
| 3 | 예산 배분 | 채널별, 캠페인별 예산 배분표 + 근거 |
| 4 | 입찰 전략 | CPC/CPM/CPA 목표 단가 + 입찰 방식 선택 근거 |
| 5 | 소재 매트릭스 | 소재 유형 x 타깃 조합 매트릭스 (최소 9개 조합) |
| 6 | 실험 계획 | A/B 테스트 변수, 가설, 성공 기준, 기간, 표본 크기 |
| 7 | 성과 예측 | 예상 노출/클릭/전환/ROAS 범위 (하한-상한) |
| 8 | 스케일업 기준 | 성과 기반 예산 증감 트리거 조건 |

### 팀6: 데이터/분석 (T06)

| # | 기준 | 통과 조건 |
|---|------|-----------|
| 1 | KPI 정의 | 각 KPI의 정의, 계산식, 데이터 소스 명시 |
| 2 | 측정 환경 | 트래킹 코드 설치 확인, UTM 규칙, 전환 이벤트 정의 |
| 3 | 대시보드 구성 | 실시간 모니터링 항목, 업데이트 주기, 접근 권한 |
| 4 | 리포트 포맷 | 일간/주간/월간 리포트 템플릿 완성 |
| 5 | 이상치 기준 | 성과 이상 감지 기준 (±30% 등) + 알림 체계 |
| 6 | 어트리뷰션 모델 | 멀티터치 어트리뷰션 모델 선택 근거 |
| 7 | 데이터 정합성 | 플랫폼 간 데이터 오차 범위 확인 및 보정 방법 |

## 5. 게이트 통과 절차

### 5.1 제출 단계
1. 산출물 팀이 QA 체크리스트(`qa_checklists.md`) 자체 점검 완료
2. 핸드오버 포맷 작성 완료
3. PM(팀0)에게 제출

### 5.2 1차 검토 (PM)
1. 공통 체크리스트 12개 항목 확인
2. 컴플라이언스 게이트 10개 항목 확인
3. 해당 팀 산출물 품질 기준 확인
4. **24시간 이내** 판정 결과 회신

### 5.3 판정 후 프로세스

#### 통과 시
```
PM -> 후속 팀에 핸드오버 전달 -> 후속 팀 24시간 내 수령 확인
```

#### 수정 시
```
PM -> 원 팀에 수정 포인트 리스트 전달
-> 원 팀 24시간 내 수정 후 재제출
-> PM 재검토 (12시간 내)
-> 2회 연속 수정 시 PM + 원 팀 미팅
```

#### 반려 시
```
PM -> 원 팀에 반려 사유서 전달
-> PM + 원 팀 + 이전 팀 3자 미팅
-> 요청 티켓 재작성 또는 이전 산출물 수정
-> 전체 재작업 후 재제출
```

## 6. 에스컬레이션 규칙

| 상황 | 에스컬레이션 대상 | 대응 시한 |
|------|-------------------|-----------|
| 수정 2회 연속 | PM이 직접 미팅 주재 | 4시간 내 미팅 |
| 반려 발생 | PM + 관련 팀 리더 3자 미팅 | 8시간 내 미팅 |
| 컴플라이언스 위반 | PM + 법무/규제 담당 즉시 보고 | 2시간 내 보고 |
| 기한 초과 (24시간+) | PM이 대체 방안 수립 | 초과 즉시 |
| 동일 산출물 3회 반려 | 프로젝트 리더 에스컬레이션 | 즉시 |
| 팀 간 품질 기준 이견 | PM이 판정 기준 재정의 미팅 주재 | 24시간 내 |
| 외부 이해관계자 피드백 충돌 | PM + 클라이언트 커뮤니케이션 | 업무일 기준 1일 |

### 에스컬레이션 기록

모든 에스컬레이션은 다음 형식으로 기록한다:

```
[에스컬레이션]
일시:
산출물:
판정 이력: (Pass/Revise/Reject 히스토리)
사유:
참석자:
결정 사항:
후속 조치 및 기한:
```
