# 네이밍 컨벤션

> 하캄 에이전시 파일명, 버전, 폴더 구조 표준 규칙

---

## 1. 파일명 규칙

### 기본 구조

```
{프로젝트코드}-{팀코드}-{산출물유형}-v{버전}-{날짜}
```

### 예시

```
HKM-2024-T01-persona-v1.0-240115
HKM-2024-T02-headline-v2.1-240120
HKM-2024-T04-script-reel-v1.0-240125
HKM-2024-T06-report-weekly-v1.0-240201
```

### 파일명 작성 규칙

| 규칙 | 설명 |
|------|------|
| 구분자 | 하이픈(`-`) 사용. 언더스코어(`_`)나 공백 금지 |
| 대소문자 | 모두 소문자 (프로젝트 코드의 알파벳 부분은 대문자 허용) |
| 날짜 형식 | YYMMDD (6자리). 예: 240115 = 2024년 1월 15일 |
| 확장자 | 파일 형식에 따라 별도 표기 (`.pdf`, `.pptx`, `.csv`, `.xlsx`, `.md`) |
| 한글 금지 | 파일명에 한글 사용 금지. 내용 설명은 핸드오버 포맷에서 처리 |
| 최대 길이 | 파일명 전체 60자 이내 (확장자 포함) |

## 2. 프로젝트 코드

### 형식

```
{브랜드약어}-{연도}
```

| 구성 요소 | 규칙 | 예시 |
|-----------|------|------|
| 브랜드 약어 | 영문 대문자 2~4자 | HKM, SLV, BRD |
| 연도 | 4자리 | 2024, 2025 |

### 예시
- `HKM-2024` : 하캄 2024년 프로젝트
- `SLV-2025` : 실버나인 2025년 프로젝트
- `BRD-2024` : 브릿지 2024년 프로젝트

### 동일 브랜드 다수 프로젝트 시
연도 뒤에 순번 추가:
```
HKM-2024-01  (1차 캠페인)
HKM-2024-02  (2차 캠페인)
```

## 3. 팀 코드

| 코드 | 팀명 | 역할 |
|------|------|------|
| T00 | PM/오케스트레이터 | 프로젝트 관리, 품질 게이트, 일정 조율 |

| T02 | 전략/크리에이티브 | 메시지 전략, 헤드라인, 랜딩페이지 IA |
| T03 | 콘텐츠/SEO | 블로그, 키워드, 콘텐츠 캘린더 |
| T04 | 소셜/쇼트폼 | 릴스, 틱톡, 소셜 콘텐츠 대본 |

## 5. 버전 관리 규칙

### 버전 번호 체계

```
v{메이저}.{마이너}
```

| 구분 | 변경 시점 | 예시 |
|------|-----------|------|
| **메이저 (v1 -> v2)** | 방향성/구조가 근본적으로 변경될 때 (반려 후 재작업) | v1.0 -> v2.0 |
| **마이너 (v1.0 -> v1.1)** | 부분 수정, 피드백 반영 (수정 판정 후 보완) | v1.0 -> v1.1 |

### 버전 변경 규칙

| 상황 | 버전 변경 |
|------|-----------|
| 최초 제출 | v1.0 |
| 수정(Revise) 판정 후 재제출 | v1.1, v1.2, ... |
| 반려(Reject) 후 재작업 | v2.0 |
| 2차 반려 후 재작업 | v3.0 |
| 통과 후 클라이언트 피드백 반영 | v1.1 (마이너) 또는 v2.0 (메이저 변경 시) |
| 오탈자/서식 수정 (내용 변경 없음) | 버전 유지, 파일명의 날짜만 갱신 |

### 버전 이력 관리

각 산출물 파일의 첫 페이지 또는 상단에 다음 형식으로 이력을 기록한다:

```
버전 이력
| 버전 | 날짜 | 변경 내용 | 작성자 |
|------|------|-----------|--------|
| v1.0 | 240115 | 최초 작성 | T01 |
| v1.1 | 240117 | 페르소나 B 연령대 수정, 데이터 보강 | T01 |
| v2.0 | 240122 | 세그먼트 재설계 (4개 -> 3개 통합) | T01 |
```

## 6. 폴더 구조

### 프로젝트 루트

```
{프로젝트코드}/
├── 00-pm/                    # T00 PM 산출물
│   ├── brief/
│   ├── timeline/
│   ├── gate-results/
│   └── meeting-notes/
├── 01-research/              # T01 리서치/오퍼
│   ├── persona/
│   ├── journey/
│   ├── offer/
│   ├── competitor/
│   └── raw-data/
├── 02-strategy/              # T02 전략/크리에이티브
│   ├── message/
│   ├── headline/
│   ├── landing-ia/
│   ├── creative-brief/
│   └── copy/
├── 03-content/               # T03 콘텐츠/SEO
│   ├── keyword/
│   ├── calendar/
│   ├── article/
│   └── seo-audit/
├── 04-social/                # T04 소셜/쇼트폼
│   ├── script/
│   ├── storyboard/
│   ├── shooting-guide/
│   └── social-copy/
├── 05-performance/           # T05 퍼포먼스
│   ├── campaign/
│   ├── media-plan/
│   ├── ad-matrix/
│   └── experiment/
├── 06-data/                  # T06 데이터/분석
│   ├── kpi/
│   ├── tracking/
│   ├── dashboard/
│   └── report/
│       ├── daily/
│       ├── weekly/
│       └── monthly/
└── archive/                  # 이전 버전 보관
    └── {팀폴더별 아카이브}
```

### 폴더 규칙

| 규칙 | 설명 |
|------|------|
| 최신 버전만 활성 폴더에 유지 | 이전 버전은 `archive/` 폴더로 이동 |
| 폴더명 소문자 | 모든 폴더명은 영문 소문자 + 하이픈 |
| 깊이 제한 | 최대 4단계까지만 허용 (프로젝트/팀/유형/파일) |
| 임시 파일 금지 | `temp`, `draft`, `test` 등 임시 폴더/파일 금지. 작업 중 파일도 버전 관리 |
| README 불필요 | 각 폴더에 README 작성 금지. 파일명과 핸드오버 포맷으로 충분 |
