# QA 체크리스트

> 하캄 에이전시 산출물 품질 보증을 위한 공통 및 팀별 점검표

---

## 1. 공통 체크리스트

모든 산출물은 팀별 체크리스트 점검 **전에** 아래 공통 항목을 먼저 통과해야 한다.
공통 항목 1건이라도 미충족 시 팀별 점검으로 넘어가지 않는다.

### 포맷/형식

- [ ] 핸드오버 포맷이 모든 필드 빠짐없이 작성되었다
- [ ] 파일명이 네이밍 컨벤션(`naming_conventions.md`)을 준수한다
- [ ] 버전 번호가 정확히 표기되었다
- [ ] 버전 이력이 산출물 상단에 기록되었다
- [ ] 핸드오버의 핵심 요약이 정확히 5줄이다

### 내용/품질

- [ ] 타깃 페르소나가 구체적으로 명시되어 있다
- [ ] CTA(Call to Action)가 명확하게 포함되어 있다
- [ ] 모든 사실적 주장에 데이터 출처 또는 근거가 있다
- [ ] 이전 팀 산출물의 핵심 방향과 일관성을 유지한다
- [ ] 맞춤법, 띄어쓰기, 표기법 오류가 없다
- [ ] KPI 또는 성과 지표와의 연결이 명시되어 있다
- [ ] 다음 팀이 추가 질의 없이 작업 착수할 수 있을 만큼 충분한 정보가 있다

### 컴플라이언스

- [ ] "최고", "1위", "가장" 등 최상급 표현이 없다 (입증 자료 없는 경우)
- [ ] 의료/건강 효능 암시 표현이 없다
- [ ] 경쟁사 비하 또는 근거 없는 비교 표현이 없다
- [ ] 개인정보 노출이 없다 (고객명, 연락처, 주소 등)
- [ ] 이미지/음원/폰트 저작권이 확인되었다
- [ ] 광고/협찬 표기 의무가 준수되었다
- [ ] 해당 채널 플랫폼 광고 정책을 위반하지 않는다
- [ ] 할인/가격 표기가 정확하고 기간이 명시되어 있다

## 2. 팀1: 리서치/오퍼 (T01)

### 페르소나 완성도

- [ ] 최소 3개 세그먼트가 도출되었다
- [ ] 각 페르소나에 인구통계 정보가 포함되어 있다 (연령, 성별, 거주지, 직업, 소득)
- [ ] 각 페르소나에 심리적 특성이 포함되어 있다 (가치관, 라이프스타일, 관심사)
- [ ] 각 페르소나에 행동 패턴이 포함되어 있다 (구매 빈도, 채널, 의사결정 방식)
- [ ] 각 페르소나에 미디어 소비 습관이 포함되어 있다 (주 사용 SNS, 콘텐츠 선호, 활동 시간대)
- [ ] 페르소나 간 차별점이 명확히 구분된다 (중복 세그먼트 아님)

### 구매 여정 맵

- [ ] 인지 -> 관심 -> 탐색 -> 비교 -> 구매 -> 재구매 단계가 모두 포함되어 있다
- [ ] 각 단계별 주요 터치포인트가 매핑되어 있다
- [ ] 각 단계별 고객 감정/니즈가 기술되어 있다
- [ ] 각 단계별 이탈 요인이 식별되어 있다
- [ ] 각 단계별 우리의 대응 액션이 제안되어 있다

### 오퍼 구조

- [ ] 각 페르소나별 핵심 가치 제안이 1개 이상 정의되었다
- [ ] 가격 전략이 명시되었다 (정가, 할인가, 번들 옵션)
- [ ] 경쟁사 대비 차별화 포인트가 최소 3개 나열되었다
- [ ] 차별화 포인트에 대한 증거/뒷받침 데이터가 있다
- [ ] 시즌성/시의성 검토가 완료되었다
- [ ] 업셀/크로스셀 기회가 식별되었다

### 데이터 신뢰도

- [ ] 데이터 출처가 모두 명시되어 있다 (1차/2차/3차 구분)
- [ ] 표본 크기와 수집 기간이 기재되어 있다
- [ ] 표본 편향 여부가 검토되었다 (지역, 연령, 채널 편중)
- [ ] 정량 데이터와 정성 데이터가 모두 포함되어 있다

## 3. 팀2: 전략/크리에이티브 (T02)

### 메시지 전략

- [ ] 페르소나별 핵심 메시지(메인 카피)가 정의되었다
- [ ] 페르소나별 보조 메시지가 최소 3개 정의되었다
- [ ] 메시지가 오퍼의 가치 제안과 직접 연결된다
- [ ] 전 채널 공통 브랜드 메시지가 일관성을 유지한다
- [ ] 메시지의 감성적 소구점과 이성적 소구점이 균형을 이룬다

### 헤드라인

- [ ] 페르소나당 최소 5개 헤드라인 후보가 있다
- [ ] 헤드라인 유형이 다양하다 (감성/이성/긴급성/호기심/사회적 증거 등 3가지 이상)
- [ ] 각 헤드라인의 A/B 테스트 변수가 명시되어 있다
- [ ] 채널별 글자 수 제한을 고려하여 길이가 조정되었다
- [ ] 컴플라이언스 위반 표현이 없다 (최상급, 효능 암시 등)

### 톤앤매너

- [ ] 브랜드 보이스 정의가 완성되었다 (형용사 3~5개)
- [ ] 채널별 톤 차이가 명시되었다 (블로그 vs SNS vs 광고)
- [ ] 사용 권장 어휘 목록이 있다
- [ ] 사용 금지 어휘 목록이 있다
- [ ] 말투/문체 예시가 좋은 예/나쁜 예로 제시되었다

### 랜딩페이지 IA

- [ ] 히어로 섹션 구성이 정의되었다 (헤드라인, 서브카피, CTA, 비주얼)
- [ ] 문제 제기 -> 솔루션 -> 증거 -> CTA 흐름이 완성되었다
- [ ] 사회적 증거(리뷰, 수치, 인증) 섹션이 포함되었다
- [ ] 모바일 우선 레이아웃이 고려되었다
- [ ] 스크롤 깊이별 CTA 배치 계획이 있다

### 비주얼 디렉션

- [ ] 무드보드 또는 레퍼런스 이미지가 3장 이상 첨부되었다
- [ ] 컬러 팔레트(주색/보조색/강조색)가 정의되었다
- [ ] 타이포그래피 방향이 제시되었다
- [ ] 이미지 스타일(사진/일러스트/그래픽) 가이드가 있다

## 4. 팀3: 콘텐츠/SEO (T03)

### 키워드 리서치

- [ ] 메인 키워드 + 롱테일 키워드 그룹이 최소 5개 클러스터로 구성되었다
- [ ] 각 키워드의 월간 검색량이 표기되었다
- [ ] 각 키워드의 경쟁 난이도가 평가되었다
- [ ] 각 키워드의 검색 의도가 분류되었다 (정보/상업/거래/탐색)
- [ ] 자사 현재 순위(있는 경우)가 표기되었다
- [ ] 키워드-페르소나-구매여정 단계 매핑이 완료되었다

### 콘텐츠 캘린더

- [ ] 최소 4주 분량의 일정이 수립되었다
- [ ] 각 콘텐츠에 게시 채널이 명시되었다
- [ ] 각 콘텐츠에 콘텐츠 형식이 명시되었다 (블로그/인포그래픽/리스티클 등)
- [ ] 각 콘텐츠에 타깃 키워드가 지정되었다
- [ ] 각 콘텐츠에 타깃 페르소나가 지정되었다
- [ ] 각 콘텐츠에 CTA가 지정되었다
- [ ] 시즌 이벤트/기념일이 반영되었다
- [ ] 콘텐츠 간 주제 중복이 없다

### 콘텐츠 원고

- [ ] H1-H2-H3 계층 구조가 올바르다
- [ ] 메타 타이틀(60자 이내)이 작성되었다
- [ ] 메타 디스크립션(160자 이내)이 작성되었다
- [ ] 타깃 키워드가 자연스럽게 배치되었다 (키워드 스터핑 아님)
- [ ] 채널별 권장 길이를 준수한다 (블로그 2000자+)
- [ ] 내부 링크가 최소 2개 포함되었다
- [ ] 외부 링크(출처)가 포함되었다
- [ ] 이미지 ALT 태그가 준비되었다
- [ ] 원본성 검사 결과 유사도 10% 이하이다

### 내부 링크 전략

- [ ] 기존 콘텐츠와의 연결 구조가 설계되었다
- [ ] 허브 콘텐츠 -> 스포크 콘텐츠 계층이 명확하다
- [ ] 링크 앵커 텍스트가 자연스럽다
- [ ] 고아 페이지(연결 없는 페이지)가 식별 및 해소되었다

## 5. 팀4: 소셜/쇼트폼 (T04)

### 대본 완성도

- [ ] 나레이션/대사가 빠짐없이 기재되었다
- [ ] 화면에 표시될 자막/텍스트가 별도 표기되었다
- [ ] 각 컷/장면에 대한 화면 지시가 있다
- [ ] 전체 분량이 플랫폼 규격에 맞다 (릴스 30/60초, 틱톡 15/30/60초)
- [ ] 대본 분량 읽기 테스트를 완료했다 (실제 초 단위 타이밍)

### 훅 (첫 3초)

- [ ] 3초 이내 시선 고정 장치가 명확히 설계되었다
- [ ] 훅 유형이 명시되었다 (질문형/충격형/공감형/대비형/결과먼저형)
- [ ] 훅이 타깃 페르소나의 핵심 고민/욕구와 연결된다
- [ ] 훅이 나머지 콘텐츠의 시청을 유도한다 (궁금증 유발)
- [ ] 음소거 상태에서도 훅이 작동한다 (자막/비주얼 장치)

### 촬영 지시 구체성

- [ ] 카메라 앵글이 컷별로 지정되었다 (클로즈업/미디엄/와이드)
- [ ] 조명 방향이 명시되었다 (자연광/인공조명, 방향)
- [ ] 필요한 소품 목록이 있다
- [ ] 모델/출연자 동선이 기술되었다
- [ ] 컷 전환 타이밍과 방식이 지정되었다 (점프컷/슬라이드/줌 등)
- [ ] 배경 음악/효과음 방향이 제시되었다
- [ ] 촬영 장소 요건이 명시되었다

### CTA 및 전환

- [ ] 영상 끝 5초 이내에 CTA가 삽입되었다
- [ ] CTA 유형이 명시되었다 (댓글/저장/공유/링크인바이오/팔로우)
- [ ] CTA가 시청자 행동을 구체적으로 유도한다 ("링크인바이오에서 확인" 등)
- [ ] 캡션에 CTA가 반복되었다

### 플랫폼 최적화

- [ ] 현재 플랫폼 트렌드(음원/챌린지/포맷)가 반영되었다
- [ ] 해시태그 전략이 수립되었다 (메인 3~5개 + 롱테일 10~15개)
- [ ] 최적 게시 시간이 제안되었다
- [ ] 자막 크기/위치/배경 처리 기준이 명시되었다
- [ ] 세로 화면(9:16) 비율에 맞는 구성이다

## 6. 팀5: 퍼포먼스 (T05)

### 캠페인 구조

- [ ] 캠페인 -> 광고 세트 -> 소재 3계층 구조가 설계되었다
- [ ] 각 캠페인의 목표(인지/트래픽/전환)가 명시되었다
- [ ] 캠페인 목표와 KPI의 연결이 명확하다
- [ ] 캠페인 간 오디언스 중복이 관리되었다
- [ ] 캠페인 시작/종료일이 명시되었다

### 타깃팅 매트릭스

- [ ] 페르소나별 타깃팅 조건이 구체적으로 정의되었다
- [ ] 관심사 타깃팅 키워드가 나열되었다
- [ ] 행동 타깃팅 조건이 정의되었다
- [ ] 커스텀/룩어라이크 오디언스 소스가 명시되었다
- [ ] 리타깃팅 조건과 기간이 설정되었다
- [ ] 제외 타깃 조건이 정의되었다

### 예산 및 입찰

- [ ] 채널별 예산 배분이 완료되었다
- [ ] 예산 배분 근거가 명시되었다 (시장 데이터, 과거 성과, 벤치마크)
- [ ] 목표 CPC/CPM/CPA 단가가 설정되었다
- [ ] 입찰 방식이 선택되었다 (자동/수동, 목표 ROAS 등)
- [ ] 일 예산 한도가 설정되었다
- [ ] 예산 소진 속도 모니터링 기준이 있다

### 소재 매트릭스

- [ ] 소재 유형 x 타깃 조합 매트릭스가 최소 9개 조합이다
- [ ] 각 조합에 대한 예상 성과가 기재되었다
- [ ] 소재별 메시지와 팀2 메시지 프레임워크가 일치한다
- [ ] 소재 피로도 관리 계획이 있다 (교체 주기)

### 실험 계획

- [ ] A/B 테스트 변수가 명확히 정의되었다 (1 테스트 = 1 변수)
- [ ] 각 테스트의 가설이 기술되었다
- [ ] 성공/실패 기준이 수치로 명시되었다
- [ ] 테스트 기간이 설정되었다
- [ ] 필요 표본 크기가 계산되었다 (통계적 유의성 기준)
- [ ] 테스트 결과 후속 액션 계획이 있다 (승자 소재 스케일업 등)

### 스케일업 기준

- [ ] 예산 증액 트리거 조건이 수치로 정의되었다
- [ ] 예산 감액/중단 트리거 조건이 정의되었다
- [ ] 단계별 증액 폭이 설정되었다 (예: 20%씩 증액)
- [ ] 스케일업 시 모니터링 강화 항목이 명시되었다

## 7. 팀6: 데이터/분석 (T06)

### KPI 정의

- [ ] 각 KPI의 정식 명칭이 정의되었다
- [ ] 각 KPI의 계산식이 명시되었다 (예: 전환율 = 전환 수 / 클릭 수 x 100)
- [ ] 각 KPI의 데이터 소스가 명시되었다 (GA4, 광고 플랫폼, CRM 등)
- [ ] 각 KPI의 목표 수치가 설정되었다
- [ ] 선행 지표(Leading)와 후행 지표(Lagging)가 구분되었다
- [ ] North Star Metric이 정의되었다
- [ ] KPI 간 계층 구조(트리)가 설계되었다

### 측정 환경

- [ ] 트래킹 코드(GA4, 픽셀 등) 설치가 확인되었다
- [ ] UTM 파라미터 규칙이 정의되었다 (source, medium, campaign, content, term)
- [ ] 전환 이벤트가 정의되었다 (이벤트명, 트리거 조건, 파라미터)
- [ ] 크로스 도메인 트래킹이 필요한 경우 설정이 확인되었다
- [ ] 쿠키 동의/개인정보 보호 설정이 반영되었다
- [ ] 데이터 수집 테스트가 완료되었다 (실제 이벤트 발생 확인)

### 대시보드

- [ ] 실시간 모니터링 항목이 정의되었다
- [ ] 데이터 업데이트 주기가 명시되었다 (실시간/시간별/일별)
- [ ] 대시보드 접근 권한이 설정되었다
- [ ] 핵심 지표가 한 화면에서 파악 가능하다
- [ ] 필터/드릴다운 기능이 설계되었다 (채널별, 기간별, 캠페인별)
- [ ] 이상치 알림 기준이 설정되었다 (목표 대비 ±30% 등)

### 리포트

- [ ] 일간 리포트 템플릿이 완성되었다 (주요 수치 + 전일 대비)
- [ ] 주간 리포트 템플릿이 완성되었다 (주간 트렌드 + 인사이트 + 액션)
- [ ] 월간 리포트 템플릿이 완성되었다 (목표 대비 달성률 + 원인 분석 + 제안)
- [ ] 리포트 배포 대상과 일정이 정의되었다
- [ ] 리포트에 "So What"(인사이트)과 "Now What"(액션 제안)이 포함된다

### 어트리뷰션

- [ ] 어트리뷰션 모델이 선택되었다 (라스트클릭/선형/시간감쇠/데이터기반)
- [ ] 모델 선택 근거가 명시되었다
- [ ] 어트리뷰션 윈도우(기간)가 설정되었다
- [ ] 플랫폼 간 데이터 오차 범위가 확인되었다
- [ ] 오차 보정 방법이 문서화되었다

### 데이터 품질

- [ ] 데이터 정합성 검증 프로세스가 수립되었다
- [ ] 이상치 탐지 기준이 정의되었다
- [ ] 데이터 백업 주기가 설정되었다
- [ ] 데이터 접근 로그가 관리된다
- [ ] 원데이터 보존 기간이 정의되었다

## 8. 체크리스트 사용 절차

### 8.1 자체 점검 (제출 전)

1. 산출물 작성 팀이 해당 팀 체크리스트를 **전 항목** 점검
2. 공통 체크리스트를 점검
3. 미충족 항목이 있으면 수정 후 재점검
4. 모든 항목 충족 확인 후 핸드오버 포맷 작성
5. PM(T00)에게 제출

### 8.2 PM 검토 (게이트 심사)

1. 공통 체크리스트 확인
2. 컴플라이언스 게이트 확인 (`decision_gates.md` 참조)
3. 해당 팀 체크리스트 확인
4. 판정: 통과 / 수정 / 반려

### 8.3 체크리스트 갱신

- 프로젝트 완료 후 회고(Retrospective)에서 체크리스트 항목 추가/삭제/수정 검토
- 신규 컴플라이언스 이슈 발생 시 즉시 반영
- 분기 1회 전체 체크리스트 리뷰
