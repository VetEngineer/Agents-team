# 하캄솔루션 측정 규칙

이 문서는 하캄솔루션 에이전트 에이전시의 측정, 실험, 리포팅에 적용되는 규칙을 정의한다. 데이터 없는 마케팅은 추측이고, 학습 없는 데이터는 숫자 나열이다.

---

## 1. 변수 1개 규칙

### 원칙

한 번의 실험에서 변경하는 변수는 **정확히 1개**다. 이 규칙을 위반한 실험 계획은 승인되지 않는다.

### 변수의 정의

"변수"란 실험 결과에 영향을 줄 수 있는 요소를 말한다. 마케팅에서 주요 변수는 다음과 같다:

| 카테고리 | 변수 예시 |
|----------|----------|
| 소재 | 헤드라인, 본문, 이미지, 영상, CTA 문구 |
| 타깃 | 연령대, 성별, 지역, 관심사, 커스텀 오디언스 |
| 채널/배치 | 피드/스토리/릴스, 검색/디스플레이, 모바일/PC |
| 랜딩 | 히어로 섹션, 폼 위치, 폼 필드 수, CTA 버튼 |
| 입찰/예산 | 입찰 전략, 일 예산, 총 예산 |
| 시간 | 게시 시간, 요일, 시즌 |

### 실험 설계 템플릿

```
실험명: [구체적 이름]
기간: YYYY-MM-DD ~ YYYY-MM-DD (최소 7일)
가설: "[변수 A]를 [현재값]에서 [변경값]으로 바꾸면 [KPI]가 [방향]할 것이다"
변경 변수: [정확히 1개]
고정 변수: [변경하지 않는 모든 요소 나열]
성공 기준: [KPI] [수치] 이상/이하 (예: CTR 0.5%p 이상 개선)
최소 표본: [클릭 수 또는 노출 수] (통계적 유의를 위한 최소 기준)
판정 방법: [A 승리 → 적용 / B 승리 → 적용 / 무승부 → 새 가설]
```

### 위반 사례와 교정

| 상황 | 위반 여부 | 교정 방법 |
|------|----------|----------|
| 헤드라인과 이미지를 동시에 바꿈 | 위반 | 2개 실험으로 분리 (1주 헤드라인, 2주 이미지) |
| 타깃 연령대를 바꾸면서 소재도 연령대에 맞게 변경 | 위반 | 소재를 동일하게 유지하고 타깃만 변경, 또는 타깃을 고정하고 소재만 변경 |
| CTA 문구만 변경 (버튼 색상/위치는 동일) | 적합 | - |
| 새 채널을 추가하면서 기존 채널 예산을 줄임 | 위반 | 기존 채널 예산 유지한 채 신규 채널 별도 예산으로 테스트 |

## 2. KPI 설계 원칙

### 구조: 주 KPI 1개 + 보조 KPI 2개

모든 프로젝트는 아래 구조로 KPI를 설계한다. KPI가 3개를 초과하면 집중이 흐려진다.

```
주 KPI (1개): 프로젝트의 성공을 판단하는 핵심 지표
├── 보조 KPI A: 주 KPI에 영향을 주는 선행 지표
└── 보조 KPI B: 주 KPI의 건전성을 확인하는 균형 지표
```

### 업종별 KPI 설계 예시

**치과 (상담 예약 목표)**
```
주 KPI: 월간 상담 예약 건수 (목표: 60건)
├── 보조 A: 랜딩 전환율 CVR (목표: 5% 이상)
└── 보조 B: 상담 → 시술 전환율 (목표: 40% 이상)
```

**세무사 (상담 문의 목표)**
```
주 KPI: 월간 상담 문의 건수 (목표: 30건)
├── 보조 A: 블로그 유입 → 문의 전환율 (목표: 3% 이상)
└── 보조 B: CPL 리드당 비용 (목표: 5만원 이하)
```

**인테리어 (견적 요청 목표)**
```
주 KPI: 월간 견적 요청 건수 (목표: 40건)
├── 보조 A: 포트폴리오 페이지 조회 수 (목표: 2,000회)
└── 보조 B: 견적 요청 → 계약 전환율 (목표: 20% 이상)
```

### KPI 정의서 필수 항목

각 KPI는 아래 항목을 반드시 포함해야 한다:

| 항목 | 내용 | 예시 |
|------|------|------|
| KPI명 | 지표의 정확한 이름 | 월간 상담 예약 건수 |
| 정의 | 무엇을 세는지 명확히 | 웹사이트 예약 폼 제출 + 전화 상담 예약 합계 |
| 계산 방법 | 수식 또는 데이터 소스 | GA4 form_submit 이벤트 + CRM 전화 예약 로그 |
| 목표값 | 구체적 수치 | 월 60건 |
| 현재값(베이스라인) | 개선 전 현재 수준 | 월 30건 |
| 관측 주기 | 얼마나 자주 확인하는지 | 주간 (매주 월요일) |
| 데이터 소스 | 어디서 수집하는지 | GA4 + CRM 엑셀 |

## 3. 데이터 수집 표준

### 수집 계층

마케팅 퍼널의 각 단계에서 수집해야 하는 데이터를 정의한다.

```
[노출] → [클릭] → [랜딩 도착] → [주요 행동] → [전환] → [후속 전환]
```

| 단계 | 수집 데이터 | 도구 |
|------|-----------|------|
| 노출 | 노출 수, 도달 수, CPM | 광고 플랫폼 (메타/네이버/구글) |
| 클릭 | 클릭 수, CTR, CPC | 광고 플랫폼 |
| 랜딩 도착 | 세션 수, 이탈률, 체류 시간 | GA4 |
| 주요 행동 | 스크롤 깊이, 버튼 클릭, 페이지 조회 | GA4 이벤트 |
| 전환 | 폼 제출, 전화 클릭, 예약 완료 | GA4 전환 이벤트 |
| 후속 전환 | 상담 완료, 계약/결제 | CRM / 수기 기록 |

### UTM 태깅 규칙

모든 외부 유입 링크에는 UTM 파라미터를 필수 적용한다.

```
utm_source: 유입 출처 (naver, meta, google, instagram, kakao)
utm_medium: 매체 유형 (cpc, organic, social, email, referral)
utm_campaign: 캠페인명 (YYYYMM_캠페인설명)
utm_content: 소재 구분 (headline_a, image_b, video_01)
utm_term: 키워드 (검색광고 시)
```

**예시**:
```
https://example.com/landing?utm_source=naver&utm_medium=cpc&utm_campaign=202603_implant&utm_content=headline_a&utm_term=강남임플란트
```

### 전환 이벤트 정의 표준

| 이벤트명 | 트리거 | 파라미터 | 전환 여부 |
|----------|--------|----------|----------|
| page_view | 페이지 로드 | page_title, page_location | N |
| scroll_50 | 페이지 50% 스크롤 | page_title | N |
| cta_click | CTA 버튼 클릭 | cta_type (call, form, kakao) | N |
| form_start | 예약 폼 첫 필드 입력 | form_name | N |
| form_submit | 예약 폼 제출 완료 | form_name, service_type | **Y** |
| phone_click | 전화번호 클릭 | page_title | **Y** |
| kakao_click | 카카오 상담 클릭 | page_title | **Y** |

## 4. 리포트 작성 원칙

### 핵심 규칙: 학습 3개 + 액션 3개

리포트의 목적은 "숫자를 보여주는 것"이 아니라 **"학습을 공유하고 다음 행동을 결정하는 것"**이다.

### 주간 리포트 구조

```
[주간 리포트] YYYY-MM-DD ~ YYYY-MM-DD

1. 이번 주 핵심 수치
   - 주 KPI: [수치] (목표 대비 OO%)
   - 보조 KPI A: [수치]
   - 보조 KPI B: [수치]

2. 학습 3가지
   (1) [관찰]: 무엇이 일어났는가
       [원인 가설]: 왜 그런 것으로 보이는가
   (2) [관찰]: ...
       [원인 가설]: ...
   (3) [관찰]: ...
       [원인 가설]: ...

3. 다음 주 액션 3가지
   (1) [액션]: 무엇을 할 것인가
       [기대 효과]: 어떤 수치가 어떻게 변할 것으로 보는가
       [담당]: 누가
       [기한]: 언제까지
   (2) [액션]: ...
   (3) [액션]: ...

4. 리스크/블로커 (있을 경우)
   -

5. 채널별 상세 (부록)
   [표 형태로 채널별 주요 지표]
```

### 리포트 작성 금지 사항

| 금지 | 이유 | 대체 |
|------|------|------|
| "CTR이 2.3%입니다" (끝) | 학습이 없다 | "CTR이 2.3%로 전주 대비 0.5%p 상승. 원인: 헤드라인 A에서 지역명을 추가한 효과로 추정" |
| "성과가 좋습니다" | 기준이 없다 | "목표 대비 120% 달성. 특히 OO 세그먼트에서 초과 달성" |
| "더 개선하겠습니다" | 구체적이지 않다 | "다음 주 CTA 문구를 변경하여 CVR 0.3%p 개선을 목표" |
| 숫자만 나열한 표 | 인사이트가 없다 | 표 위에 핵심 학습을 문장으로 기술 |

## 5. 실험 설계 원칙

### 실험 우선순위 매트릭스

모든 실험 아이디어는 Impact(기대 효과)와 Effort(실행 난이도)로 점수를 매기고 우선순위를 정한다.

```
          높은 Impact
               │
    ┌──────────┼──────────┐
    │  Quick   │  Major   │
    │  Wins    │ Projects │
    │ (먼저)   │ (계획 후) │
────┼──────────┼──────────┤───
    │  Fill-   │  Money   │
    │  ins     │  Pit     │
    │ (여유시) │ (하지마) │
    └──────────┼──────────┘
               │
          낮은 Impact
   낮은 Effort ────── 높은 Effort
```

### 점수 기준

**Impact (1-5점)**
| 점수 | 기준 |
|------|------|
| 5 | 주 KPI에 직접 영향, 10% 이상 개선 기대 |
| 4 | 주 KPI에 직접 영향, 5-10% 개선 기대 |
| 3 | 보조 KPI에 영향, 간접적으로 주 KPI 개선 기대 |
| 2 | 보조 KPI에 소폭 영향 |
| 1 | 효과 불확실하나 테스트할 가치 있음 |

**Effort (1-5점)**
| 점수 | 기준 |
|------|------|
| 1 | 30분 이내 세팅 가능, 추가 리소스 불필요 |
| 2 | 반나절 작업, 카피 수정 수준 |
| 3 | 1-2일 작업, 디자인/개발 소규모 투입 |
| 4 | 3-5일 작업, 다수 팀 협업 필요 |
| 5 | 1주 이상, 대규모 리소스 투입 |

### 실험 종료 판정

| 상황 | 판정 | 다음 단계 |
|------|------|----------|
| A가 B보다 통계적으로 유의하게 우수 | A 승리 | A를 기본으로 적용, 새 실험 설계 |
| 차이가 없음 (7일 경과) | 무승부 | 현행 유지, 다른 변수로 실험 전환 |
| 표본이 부족하여 판단 불가 | 연장 | 7일 연장 후 재판정 |
| B가 A보다 유의하게 우수 | B 승리 | B를 기본으로 적용, 학습 기록 |
| 두 안 모두 기존 대비 하락 | 양쪽 실패 | 원래 안으로 복귀, 원인 분석 후 새 가설 |
