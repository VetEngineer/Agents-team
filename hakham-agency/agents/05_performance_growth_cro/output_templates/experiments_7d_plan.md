# 7일 실험 계획 (3개)

> 프로젝트: [프로젝트명]
> 작성일: [날짜]
> 실험 기간: [시작일] ~ [종료일] (7일)
> 담당: Agent 05 (퍼포먼스/그로스)
> 데이터 협업: Agent 06 (데이터/최적화)

---

## 실험 원칙

1. **변수 1개 규칙**: 한 실험에서 변경하는 변수는 반드시 1개뿐이다
2. **가설 먼저**: 가설 없이 실험을 시작하지 않는다
3. **측정 가능**: 추적이 확인된 지표만 측정 대상으로 삼는다
4. **충분한 샘플**: 통계적 유의미성을 확보할 수 있는 트래픽이 있어야 한다
5. **학습 기록**: 실험 결과는 반드시 문서화하고 다음 실험에 반영한다

## 실험 1: [실험명]

### 가설

> **[X]를 [A에서 B로] 바꾸면 [Y 지표]가 [Z%] 개선될 것이다.**

| 항목 | 내용 |
|------|------|
| **실험명** | [구체적 실험명, 예: "히어로 헤드라인 문제형→혜택형 변경"] |
| **배경** | [왜 이 실험을 하는가. 현재 데이터에서 관찰된 문제점] |
| **가설** | [X를 바꾸면 Y가 Z% 개선될 것이다] |
| **변경 변수 (1개)** | [정확히 무엇을 바꾸는지. 예: "헤드라인 카피"] |

### 대조군 vs 실험군

| 구분 | 대조군 (A) | 실험군 (B) |
|------|-----------|-----------|
| 변경 요소 | [현재 상태 구체적 기술] | [변경 후 상태 구체적 기술] |
| 나머지 요소 | 동일 | 동일 |
| 트래픽 배분 | 50% | 50% |

### 측정 계획

| 항목 | 내용 |
|------|------|
| **주 측정 지표** | [전환율 / CTR / CPA 등 1개] |
| **보조 지표** | [체류시간, 이탈률 등 2개] |
| **성공 기준** | [주 지표가 X% 이상 개선되면 성공] |
| **실패 기준** | [주 지표가 X% 이상 하락하면 즉시 중단] |
| **필요 샘플** | [각 군 최소 X명 / X클릭] |
| **예상 일일 트래픽** | [X명/일] |
| **통계 유의수준** | [95% 신뢰구간] |

### 실행 일정

| 일차 | 할 일 |
|------|-------|
| D-1 | 실험 세팅 완료, 추적 코드 확인, Agent 06과 데이터 정합성 점검 |
| D1 | 실험 시작, 초기 데이터 확인 (추적 정상 작동 여부) |
| D2-3 | 중간 모니터링 (이상치 확인, 샘플 누적 확인) |
| D4 | 중간 점검 (조기 종료 기준 판단) |
| D5-6 | 데이터 누적 지속 |
| D7 | 실험 종료, 데이터 수집 마감 |
| D8 | 결과 분석, 학습 기록, 다음 액션 결정 |

### 결과 기록 (실험 후 작성)

| 항목 | 결과 |
|------|------|
| 대조군 주 지표 | [수치] |
| 실험군 주 지표 | [수치] |
| 변화율 | [+/-X%] |
| 통계 유의성 | [유의/비유의, p값] |
| 판정 | [성공 / 실패 / 무의미] |
| 학습 | [이 실험에서 배운 것 1-2문장] |
| 다음 액션 | [학습을 반영한 다음 실험 또는 적용 계획] |

## 실험 우선순위 판단 기준

실험 순서를 정할 때 다음 기준을 사용한다:

1. **임팩트 크기**: 전환율에 미치는 예상 영향이 큰 것부터
2. **실행 속도**: 빨리 세팅하고 결과를 얻을 수 있는 것부터
3. **학습 가치**: 다음 실험에 연쇄적으로 활용할 수 있는 것부터
4. **리스크**: 실패해도 기존 성과를 크게 해치지 않는 것부터
